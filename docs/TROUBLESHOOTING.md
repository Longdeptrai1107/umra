# Troubleshooting

- **Java not in PATH:** choose the absolute java.exe in the GUI. To build set JAVA_HOME to a JDK, not just a JRE. Build scripts also scan common install directories.
- **MicroEmulator fails on a new JDK:** 2.0.4 predates current JDKs and may reference removed desktop/security APIs. Select Java 8 to run the emulator; a newer JDK can still build UMRA.
- **Agent never becomes ready:** inspect Emulator console. The adapter expects the MicroEmulator 2.x classloader/Connector/Display classes. The backend waits for actual readiness and shows failure after a timeout. Java without java.instrument/retransformation support is not supported; UMRA's supported fallback is relaunching a compatible desktop JVM with its startup agent.
- **No methods:** trace begins disabled. Click Start Live Trace, then trigger a new action. The adapter traces only classes in the chosen JAR. Basic shows callbacks rather than every helper. Select Deep or Selective. Repeated/running method frames started before tracing may not have an entry record.
- **Obfuscated names:** names such as a/b are preserved. Add evidence-based aliases in Mapping. Symbol renaming does not reconstruct stripped debug information.
- **Canvas button names unavailable:** Canvas contains pixels. Use key code, pointer coordinates, receiver identity, callback stack and observed method tree; UMRA does not invent widget labels.
- **No network rows:** only HTTP/TCP streams returned through the MicroEmulator adapter are wrapped. Datagram/native/custom connection implementations need an adapter. Reads/writes must happen while capture is active. A stream opened before adapter installation cannot be retroactively wrapped.
- **Bytes hidden:** raw payload capture is opt-in in Settings. Strings and sensitive fields are redacted by default. Stop/start trace after changing capture settings.
- **Network bytes look encrypted:** observations are after the application's own encoder/encryptor. Hook a selected earlier method in Deep/Selective mode if available. The generic tool cannot claim plaintext or infer a protocol's opcode without evidence.
- **Partial tree or open call:** filters, capture start/stop/pause, exceptions, bounds or record drops can omit the relevant parent/exit. The tree only claims observed ancestry. Cross-thread causal propagation is unsupported.
- **Loss warnings or lag:** reduce scope/mode, disable field snapshots/payload, close unused client windows, stop unnecessary processes. The view caps records and virtualizes rows. Queue overflow and WS backpressure are surfaced. SQLite WASM periodically snapshots the DB file; very large recordings increase export/write cost.
- **Backend disconnected:** the renderer retries WebSocket with exponential delay. Persistent failures need an application restart. Stored history remains in the SQLite file. A crash can lose records after the last successful periodic disk snapshot.
- **E2E cannot press buttons:** tests require an unlocked Windows desktop, permission to focus native emulator windows, and a free loopback port 50123. They send real input, so don't interact with other windows while they run. Logs/screenshots and failure details are under artifacts/e2e-*.
- **Local session deletion:** Stop emulator first, then delete through Sessions. This removes the selected session's SQLite rows and its exact owned directory; it does not remove source game/emulator files.
